# Evaluation — Did It Work?

> Source: Pastore, R. (2020). *The Instructional Design and Development Process: A 'How To' Guide for Practitioners*. KDP. ISBN 9798651489978.

The phase most companies skip. Pastore: "Not all companies/organizations invest in evaluation but it is a vital step" (p. 13).

## Evaluation ≠ Assessment

(p. 102)

| Concept | What it measures |
|---|---|
| **Assessment** (in Design phase) | Whether each learning *objective* was met |
| **Evaluation** (this phase) | Whether the *training program as a whole* succeeded |

Different scope, different audience.

## Formative vs Summative

(p. 102)

| Type | When | Examples |
|---|---|---|
| **Formative** | Throughout the ID process | SME review, pilot test, beta test |
| **Summative** | After completion / at the end | ROI analysis, did students learn, course success |

Pastore's book focuses on summative evaluation — the formal "did this work" question.

## Process for summative evaluation

(pp. 102–103)

1. **Determine purpose** — what question are we answering?
2. **Develop key questions** — what specifically do we need to know?
3. **Select an evaluation model** that answers those questions.

## Kirkpatrick's Four Levels — Pastore's prescription

(Kirkpatrick, 1994; Pastore p. 103)

> "If you're going to learn one evaluation model in our field, this is the one." (p. 103)

> "[Used] over 99% of the time."

| Level | Question | How to measure |
|---|---|---|
| **L1: Satisfaction** | Did they enjoy it? | Smile sheets, post-course surveys |
| **L2: Learning** | Did learning occur? By how much? | Pretest + posttest |
| **L3: Transfer** | Are they doing it on the job? | Observe, performance data, interviews, surveys (weeks/months later) |
| **L4: ROI** | Was the investment worth it? | Pre-defined performance metric (errors, money, productivity) |

### Level 1 — Satisfaction

The cheapest level. Smile sheets at end of course. Useful but **dangerous**:

> "Learner satisfaction is not necessarily correlated with learning." (p. 104)

Don't claim a training "worked" with only L1 data.

### Level 2 — Learning

Did learners learn?

**Required:** pretest + posttest. Without a pretest you can't distinguish learning gain from prior knowledge (p. 104, echoing pp. 55–56 in Design).

Format: same assessment given before and after; calculate gain.

### Level 3 — Transfer

Are learners actually doing the new behavior on the job?

**Methods:** observation, performance data, interviews, surveys.

**Timing:** weeks, months, or a year after training. Not the day after — habits haven't formed yet.

> "Levels 3 and 4 are more difficult to capture and as a result not performed as often in most organizations." (p. 104)

### Level 4 — Return on Investment

Was the financial investment justified?

**Critical rule:** define the ROI metric **before the project starts** (pp. 104–105). Examples:

- Fewer assembly errors per unit (manufacturing)
- Reduced support ticket volume (software training)
- Increased sales close rate (sales training)
- Reduced safety incidents (compliance training)

Without an upfront metric, you'll be guessing post-hoc and the client won't accept your number.

## What's NOT in Pastore's book

- **Phillips's V model** (Phillips ROI Methodology) — adds Level 5 (ROI as a ratio). Not mentioned.
- **CIPP** (Stufflebeam) — not mentioned.
- **Brinkerhoff Success Case Method** — not mentioned.

If you want those, look elsewhere. Pastore's stance is that 99% of the time Kirkpatrick is enough.

## Evaluation Report — structure

(p. 105)

1. **Background / Client** — what was the project, who was the client
2. **Stakeholders** — who cares about the outcome
3. **Key Questions** — what we set out to answer
4. **Model selected** — Kirkpatrick (and which levels)
5. **Data Collection and Findings** — methods + results per level
6. **Recommendations** — based on findings, what next

## Common mistakes

| Mistake | Page | Consequence |
|---|---|---|
| Skipping evaluation entirely | 13 | No proof training worked; client repeats it next year hoping for luck |
| L1 only → "training worked" | 104 | Learners loved it, didn't learn anything |
| Skipping pretest | 55, 104 | Can't measure L2 learning gain |
| Defining ROI metric post-hoc | 104–105 | Client rejects the number |
| Measuring L3 transfer day after course | 104 | No habit formation yet; false negative |
| Using L1 satisfaction surveys to make L4 ROI claims | 104 | Apples to gold bars |
| Treating evaluation as one-shot | 102 | Formative checkpoints throughout ID would have caught issues earlier |

## Pre-launch evaluation planning checklist

- [ ] L1 instrument designed (smile sheet)
- [ ] L2 pretest written and validated
- [ ] L2 posttest aligned to pretest
- [ ] L3 transfer measurement plan (what, who, when, how)
- [ ] L4 ROI metric agreed with client **in writing**
- [ ] Baseline data captured (L2 pretest scores; L4 baseline performance)
- [ ] Reporting cadence agreed (when does the client see L1? L3? L4?)
- [ ] Owner identified for L3 + L4 follow-up (often outlives ID engagement)
