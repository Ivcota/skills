# Description guidance

Draft the description from the user's request, existing conversation, and source framework. Preserve user-provided trigger phrases. No separate interview artifact or approval round is required.

Only when the context is insufficient, ask one bundled question such as: "Who will use this skill, and will they mainly apply the method, diagnose existing work, or learn it? Include any phrases you would use to invoke it."

Use this shape:

> {Action and object} using {method and distinctive concept}. Use when the user mentions {direct names}, {relevant problem phrases}, or {artifact/context phrases}.

Keep it under 1024 characters and in third person. Make audience and purpose specific when known. Include natural triggers, not a quota of synonyms. Avoid broad triggers that would capture unrelated tasks, time-sensitive claims, and unrelated cross-references. Present the description with the finished skill; iterate if the user requests changes.
