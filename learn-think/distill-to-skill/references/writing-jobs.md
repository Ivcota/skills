# Optional section writers

Delegate only when independent source sections make it worthwhile. A short article or compact method can be written entirely by the main agent. A typical larger framework may benefit from two or three workers, each owning several related sections; this is a guide, not a mandatory count.

Partition by source section, not by structure/application/guardrail roles. Give each writer all relevant passages for its sections, including examples and warnings elsewhere in the source. Shared introductory definitions may overlap; avoid giving every worker the full book. Keep each assignment small enough to leave room for writing in its context window.

## Assignment

Provide only:

- Audience, intended use, output directory, and assigned section names in source order.
- Exact output paths; writers must not edit shared files or other owners' references.
- Relevant source IDs, cached text paths and ranges, and cross-section definitions.
- The per-section template and citation rules (or their paths).
- Any specific known evidence gap.

Ask the writer to read its passages and write the final reference files directly. Cover concepts, mechanisms, insights, applications, source-derived phrasing, and explicit guardrails where supported. Check its own citations while writing. Do not generate separate extraction reports, meet length quotas, or browse for extra examples to fill space.

If evidence is missing, omit the unsupported material and report the gap. Request a specific scope extension if a necessary passage lies outside the assignment; do not independently reread the whole source.

Return only completed file paths, source coverage, unresolved gaps, and proposed map corrections. Do not repeat file contents in the return message.

## Main agent ownership

The main agent maintains sources.md and the canonical section map, and writes SKILL.md, case-studies.md, and checklist.md after section writers finish. Integrate terminology and evidence pointers without rewriting sound sections. Never launch a separate verifier for each file. Use one final review; delegate that review only when independence justifies its cost.
