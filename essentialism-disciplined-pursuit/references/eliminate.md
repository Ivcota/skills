# Eliminate

Eliminate turns discernment into space. McKeown's road map says eliminating nonessentials requires both mental discipline and emotional discipline because it often means saying no to people. Source: `index_split_007.txt`.

## Use Eliminate When

- The user knows what matters but still has no room for it.
- A project or team has vague intent.
- The user needs wording for a no.
- A legacy commitment survives mainly because of sunk cost.
- Boundaries are repeatedly crossed.

## Practices

### Clarify Essential Intent

An essential intent is both meaningful and measurable. It should settle future decisions instead of requiring repeated debate.

Prompt:

- "If we could be truly excellent at only one thing, what would it be?"
- "How will we know when we have succeeded?"
- "What does this decision eliminate?"

Sources: `index_split_044.txt`.

### Dare: Say No Gracefully

Use a no that is clear, timely, and respectful.

Patterns from the chapter:

- Pause instead of filling silence.
- Use "no, but..." to offer a bounded alternative.
- Check the calendar rather than answering from pressure.
- Ask, "What should I deprioritize?"

Sources: `index_split_046.txt`-`index_split_048.txt`.

### Uncommit

Reset sunk-cost thinking by asking whether you would choose the commitment again from scratch.

Prompts:

- "If I were not already invested, would I start this now?"
- "What would I pay or trade to get this back?"
- "What is status quo bias protecting?"

Sources: `index_split_049.txt`, `index_split_050.txt`.

### Edit

Apply editing to work and life:

| Editing Move | Use |
|---|---|
| Cut | Remove what does not serve the intent. |
| Condense | Make the same contribution with less. |
| Correct | Adjust back toward purpose. |
| Edit less | Stop overworking what is already enough. |

Source: `index_split_052.txt`.

### Limit

Set boundaries before the recurring conflict. Boundaries reduce repeated direct refusals because people learn the rules of engagement.

Sources: `index_split_053.txt`, `index_split_054.txt`.

## Common Failure Modes

| Failure | Symptom | Correction |
|---|---|---|
| Pretty but vague purpose | People nod but decisions do not change. | Make intent concrete. |
| Delayed no | Other people plan around a maybe. | Give a clear no sooner. |
| Sunk-cost loyalty | Past investment decides present action. | Re-evaluate from zero. |
| Scope hoarding | Nothing can be removed. | Edit against purpose. |
| Boundary guilt | User rescues every problem. | Set rules in advance. |
