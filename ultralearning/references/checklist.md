# Ultralearning Project Workbook

Use this checklist to run a project end-to-end through Scott Young's 5-step process (Ch. XIII). Fill it in. Don't skip steps. The pre-flight section comes first because the most expensive mistake is running ultralearning when a different strategy would have worked.

---

## Pre-flight: Is ultralearning the right approach?

Ultralearning is a strategy, not a default. (Ch. XIII) Pick the right strategy first.

- [ ] Is this skill one where **improvement requires unlearning** (e.g., pronunciation, public speaking, a wrong mental model)? → Ultralearning fits.
- [ ] Or is it mostly **accumulation** of new material on top of an existing base (vocabulary growth, reading denser books on a topic you already know)? → Low-intensity habits may be enough.
- [ ] Are the **frustration barriers high** at the start? → Ultralearning fits; a habit will not survive the early plateau.
- [ ] Do you need a **legally required credential** (doctor, lawyer, licensed engineer)? → Formal education is non-negotiable. Apply ultralearning principles inside it. (Ch. XIII)
- [ ] Are you looking for **community immersion** (postgrad academic, design-school apprenticeship)? → Formal/structured education adds something ultralearning can't replicate alone. (Ch. XIII)
- [ ] Conclusion: Ultralearning is the right strategy for this project? **Yes / No**

If no, stop here and pick the better strategy. If yes, continue.

## Step 1: Do Your Research (~10% of total project time)

### Why? (Motivation)

- [ ] Is the goal **instrumental** (means to a non-learning end) or **intrinsic** (curiosity, self-development)?
- [ ] If instrumental: have I expert-interviewed at least **2 people who already have what I want** to confirm the skill actually delivers the goal? (Ch. IV — Expert Interview Method)
- [ ] Have they confirmed it? **Yes / No**

### What? (Concepts / Facts / Procedures)

|---|---|---|
|   |   |   |
|   |   |   |
|   |   |   |
|   |   |   |
|   |   |   |

- [ ] Hardest items in each column underlined?

### How? (Method)

- [ ] Default curriculum identified? (University syllabi, MOOC sequences, expert-recommended path.)
- [ ] **Emphasize** decisions made — what will I go deep on?
- [ ] **Exclude** decisions made — what will I deliberately skip?
- [ ] Primary resources identified, purchased, borrowed, or enrolled in *before* I begin? (Ch. XIII)
- [ ] Direct-practice activities identified — how the skill will actually be used? (Ch. XIII)
- [ ] Backup materials and drills bookmarked (without overwhelming the start)? (Ch. XIII)

### Scope

- [ ] **Concrete, narrow scope** stated as a single sentence?

  My scope: __________________________________________________________

  Good: "Hold a 15-minute Mandarin conversation on simple topics."
  Bad: "Learn Chinese."

## Step 2: Schedule Your Time

### Three decisions (Ch. XIII)

- [ ] **How much** time per week am I committing? __ hours/week
- [ ] **When** specifically? (Concrete days and times — same every week is best.)

  Day(s) / time(s): __________________________________________________

- [ ] **Length** of the project? __ weeks / months. (Shorter is better; break long goals into multi-month projects.)

### Calendar

- [ ] All learning blocks added to my actual calendar? (Logistical — catches conflicts. Psychological — signals seriousness.)

### Bonus step (projects ≥6 months)

- [ ] **Pilot week scheduled** before full commitment?
- [ ] After the pilot: am I burned out? If yes, retool the plan before committing — don't push through. (Ch. XIII)

## Step 3: Execute — Nine-Principle Self-Audit

Run this audit weekly while the project is live. (Ch. XIII)

| # | Principle | Question | Y / N | If no, action |
|---|---|---|---|---|
| 1 | **Metalearning** | Have I researched the typical ways, interviewed successful learners, and spent ~10% of total time preparing? |   |   |
| 2 | **Focus** | Am I focused or multitasking? Skipping sessions? How long to flow, how long sustained? |   |   |
| 3 | **Directness** | Am I practicing in the way I'll use the skill? What mental processes are missing from my practice? |   |   |
| 4 | **Drill** | Am I attacking my weakest points? What's the rate-limiting step? |   |   |
| 5 | **Retrieval** | Am I solving problems and recalling from memory, or just reading and reviewing? |   |   |
| 6 | **Feedback** | Am I getting honest feedback early, or dodging punches? Overreacting to noisy data? |   |   |
| 7 | **Retention** | Do I have a plan for long-term remembering? Spacing exposure? Overlearning critical parts? |   |   |
| 8 | **Intuition** | Could I teach this to someone else? Is it clear *why* it's true, or does it feel arbitrary? |   |   |
| 9 | **Experimentation** | Am I stuck with current methods? Do I need to branch out, develop a unique style? |   |   |

"Principles serve as directions, not destinations." (Ch. XIII) Make subtle adjustments — don't wait until the project ends.

## Step 5: Maintain / Relearn / Master — choose one

Without intervention, knowledge decays. Pick a path right after the project ends. (Ch. XIII)

### Option 1: Maintenance
- [ ] Light regular practice scheduled? (Young's language model: 30 min/week per language in year 1, 30 min/month in year 2.)
- [ ] Or: skill integrated into work/life so it gets used naturally? (Young's example: Python scripts for everyday work tasks.)
- [ ] Maintenance cadence can decay over time — forgetting itself decays. Schedule the step-down.

### Option 2: Relearning
- [ ] Accept decay; plan a refresher sprint when the skill is actually needed.
- [ ] Best for skills used infrequently. Recognize that knowing *that* a domain exists and applies to a problem type is often enough — the details can be relearned faster than first-time. (Ch. XIII)

### Option 3: Mastery
- [ ] Continued light practice toward deeper competence, OR
- [ ] Another ultralearning project on a sub-branch the first project exposed.

Pick one: **Maintenance / Relearning / Mastery**

## Common-mistake spot-check

Run before starting, mid-project, and at review. (Mistakes drawn from chs. IV–XIII.)

- [ ] Am I skipping metalearning and just diving in? → Spend ~10% preparing. (Ch. IV, XIII)
- [ ] Is my scope diffuse ("learn X") rather than narrow ("do specific task Y")? → Tighten. (Ch. XIII)
- [ ] Am I hoping to "find time" instead of scheduling? → Calendar it. (Ch. XIII)
- [ ] Is my schedule ad-hoc rather than consistent? → Consistency breeds the habit. (Ch. XIII)
- [ ] Long project with no pilot week? → Run the pilot. (Ch. XIII)
- [ ] Am I picking a comfortable proxy instead of the real task? (Duolingo instead of speaking; design theory instead of Revit.) (Ch. VI)
- [ ] Am I assuming "transfer" will happen automatically from class to real life? Research says it usually doesn't. (Ch. VI)
- [ ] Am I practicing the whole skill at once instead of isolating the weak component? (Ch. VII)
- [ ] Is most of my "study" passive re-reading? Feels like learning, isn't. (Ch. VIII)
- [ ] Am I avoiding self-tests until I "feel ready"? Test before you feel confident. (Ch. VIII)
- [ ] Am I dodging feedback to protect my ego? (Ch. IX)
- [ ] Am I overreacting to feedback that is mostly noise (one viral post, one harsh comment)? Filter for proxy signals. (Ch. IX)
- [ ] Am I cramming for what needs long-term retention? Spread it out. (Ch. X)
- [ ] Do I have a maintenance plan, or will the project just decay? (Ch. X, XIII)
- [ ] Am I pattern-matching procedures without understanding *why*? (Feynman's French-curve trap.) (Ch. XI)
- [ ] Am I nodding along while reading instead of re-deriving? "Understood" should mean I can demonstrate it. (Ch. XI)
- [ ] Have I locked into the first method that worked and stopped experimenting? Near mastery, originality is the next lever. (Ch. XII)
- [ ] When this project hit a wall, did I blame willpower? Re-diagnose at the conception layer. (Ch. XIII)
- [ ] Am I logging hours that aren't actually practice? (Benny Lewis's radio-listening trap — hours don't equal practice.) (Ch. I)
