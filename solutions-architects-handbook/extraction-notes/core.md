# Extraction Notes: Core Principle

## Thesis

Solution architecture turns business goals, constraints, stakeholder needs, and non-functional requirements into a technical blueprint that can be implemented, operated, evolved, and communicated across teams.

- **Source:** Chapter 1, pages 2-4; extracted text lines 1044-1140.
- **Evidence:** The book defines solution architecture as covering strategic and tactical considerations, extending beyond software into infrastructure, networking, security, compliance, operations, cost, and reliability.

## Supporting Claims

- A solution architecture needs to meet present business needs while laying the groundwork for future growth.
  - **Source:** Chapter 1, pages 2-3; extracted text lines 1044-1064.
- Architecture work should address technology platforms, application components, data requirements, resource needs, and NFRs such as scalability, reliability, performance, availability, security, and maintainability.
  - **Source:** Chapter 1, page 2; extracted text lines 1066-1080.
- Good architecture is a collaboration tool: documentation and visualization help business teams, developers, designers, and other stakeholders align.
  - **Source:** Chapter 1, pages 3-4; extracted text lines 1088-1108.
- The book has no explicit scoring model. The draft skill uses a diagnostic checklist, not a claimed source scoring model.
  - **Source:** No scoring model found in the cited sections or chapter summaries.
