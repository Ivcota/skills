# Design — Objectives, Assessments, Strategies

> Source: Pastore, R. (2020). *The Instructional Design and Development Process: A 'How To' Guide for Practitioners*. KDP. ISBN 9798651489978.

The non-negotiable rule: **objectives = content = assessment** (Pastore 2020, p. 51, citing Dick, Carey & Carey 2014). If those three drift apart, you can't tell whether learners learned anything.

Pastore on workflow: "I usually do all of this (task analysis, objectives, assessment, and strategy) at the same time" (p. 45). Each task gets a learning objective, every objective gets an assessment, the strategy ties everything together.

## 1. Learning objectives — ABCD format

(pp. 47–50)

Every objective has four parts:

| Part | Definition | Example |
|---|---|---|
| **A**udience | Who | the learner |
| **B**ehavior | Clear, observable action verb (NEVER "understand" or "remember") | identify |
| **C**ondition | Under what conditions | given a map of the United States |
| **D**egree | Success criterion | with 100% accuracy |

**Color-coded canonical example (p. 49):**

> "Given a map of the United States, the learner will be able to identify the state of North Carolina with 100% accuracy."

### Pro tips (pp. 49–50)

- Audience can be omitted when always "the learner" — implied.
- Degree can be omitted when always 100% — implied.
- **Behavior + Condition are non-negotiable.**
- **One action verb per objective.** One objective = one sentence.

### Banned verbs

- ❌ understand
- ❌ remember
- ❌ know
- ❌ appreciate

Why: not observable, not measurable. You can't write a fair assessment for "understand."

### Allowed verbs (examples)

- ✅ identify, define, list, describe (low-level / recall)
- ✅ apply, calculate, demonstrate, solve (mid)
- ✅ evaluate, design, critique, compose (high-level / problem-solving)

### Knowledge taxonomy — Pastore's stance (p. 46)

Pastore mentions Bloom's and Gagné's taxonomies exist but personally uses just two levels:

- **Low-level** = factual recall. Mayer (2014, p. 21) calls this "remembered but cannot be used in new situations."
- **High-level** = problem-solving / transfer. Mayer: "organized into an integrated representation."

The three Bloom domains (Bloom et al. 1956) — cognitive, affective, psychomotor — are mentioned (p. 65) but not deeply applied.

**Mager is not mentioned in this book.**

## 2. Instructional Congruency (§5.1)

Objectives = Content = Assessment.

(Dick, Carey, and Carey 2014, demonstrated in Table 5.0, pp. 51–52)

Build a three-column table for sign-off:

| Task | Objective | Assessment item |
|---|---|---|
| Identify NC on map | Given a US map, the learner will identify NC with 100% accuracy | "Click on the state of North Carolina." (interactive map item) |

If a row is missing, fix it — don't ship a misaligned course.

## 3. Assessments (§5.2, pp. 53–63)

### Formative vs Summative (p. 53)

| Type | Stakes | Examples |
|---|---|---|
| Formative | Low; informal | Interviews, observations, quizzes, homework |
| Summative | High; final | Final exam, SAT, job interview |

### Validity and Reliability (pp. 54–55)

- **Validity** — is the test measuring the right thing? Are you using the test correctly?
- **Reliability** — would scores be consistent on retest?

> "Something can be reliable but not valid. Not the other way around." (p. 54)

A scale that always reads 150 lbs (regardless of who steps on it) is **reliably wrong** (p. 55).

### Pretest is mandatory (pp. 55–56)

Without a pretest you cannot prove the intervention worked vs. the learners already knowing the content. Pastore: pretest is **mandatory** when he leads a project (p. 56).

### Question types (Table 6.0, p. 56)

| Type | Best for low-level | Best for high-level |
|---|---|---|
| True/False | ✓ | — |
| Matching | ✓ | — |
| Short Answer | ✓ | — |
| Multiple Choice | ✓ | ✓ |
| Performance | ✓ | ✓ |

### Tips for writing questions (p. 57)

- ✓ Correct answer must be correct
- ✓ Correct grammar
- ✗ Avoid "Always / Never"
- ✓ Highlight "NOT" when used
- ✗ Don't copy text verbatim from content
- ✓ Plausible distractors (wrong answers learners might pick)
- ✗ No answer patterns (don't make C the answer 70% of the time)
- ✗ Avoid "none of the above" / "all of the above"

### Multiple choice — the Swiss Army knife (p. 58)

Versatile but **hard to write well.** Distractor quality is what separates a good MC item from a bad one.

### Performance assessments (pp. 60–63)

Best when:
- Both low + high knowledge levels need testing
- Demonstration is the actual goal (e.g., welding, public speaking)
- Constructivist orientation

Require a **rubric.**

### Bad rubric red flags (p. 61)

| Smell | Why it's bad |
|---|---|
| Subjective titles ("Great / OK / Poor") | Inter-rater unreliable; learners can't game it correctly |
| Equal weight on unequal items | A typo costs as much as a wrong answer |
| Multiple criteria in one box | Rater can't separate signal from noise |
| Rubric values don't reflect actual importance | Misaligned with learning outcome |

### Good rubric pattern (Table 8.0, p. 62)

- Different sections can have different column counts (that's OK)
- Explicit point values per item (e.g., 75% / 5% / 10% / 10%)
- Objective per-box descriptions (not "Great" — describe what "great" looks like)

## 4. Instructional Strategies (§5.3)

### Three types (Smith and Ragan 2004, p. 64)

| Type | What it does | Examples |
|---|---|---|
| **Organizational** | The skeleton/outline of instruction | Gagné's 9 Events, Dick & Carey's flow |
| **Delivery** | How content motivates and engages | Keller ARCS, PBL, games, gamification |
| **Development** | How content is built | Covered in §Development (Mayer's principles) |

### Organizational: Gagné's 9 Events (Gagné 1985, p. 64)

Pastore's most-used organizational strategy. Mapping to his general phases (Table 9.0, pp. 66–67):

| Pastore phase | Gagné's 9 Events | Dick & Carey |
|---|---|---|
| Introduction | Gain attention / Inform of objective / Recall prior knowledge | Pre-instructional activities |
| Content Presentation | Present material / Provide guidance / Elicit performance / Provide feedback | Content presentation; learner participation |
| Assessment | Assess performance | Assessment (entry, pre, post) |
| Utilization | Enhance retention and transfer | Follow-through |

### Delivery strategies by phase (Table 10.0, pp. 69–70)

| Phase | Strategies that fit |
|---|---|
| Introduction | Keller's ARCS (Attention, Relevance, Confidence, Satisfaction) |
| Content presentation | PBL, game-based, worked examples, lecture, video, activities |
| Assessment | Tests, projects, assignments |
| Utilization | Job aids, apprenticeship, mentorship, coaching, sandbox/simulation, drills |

### Sandbox

A practice system on a separate server. Companies install one when rolling out a new LMS or production system so learners can practice without breaking real data (pp. 68–69).

## 5. Common mistakes in design

| Mistake | Page | Consequence |
|---|---|---|
| "Understand" or "remember" as the verb | 48 | Unmeasurable objective |
| Multiple verbs / multiple objectives in one sentence | 49 | Can't isolate what learner missed |
| Misaligning objective level with task level | 47 | Quality drops; expectations wrong |
| Writing the objective as the assessment | 49 | Tautological; teaches nothing new |
| Skipping pretest | 55–56 | Can't prove learning gain |
| Bad rubrics (subjective titles, equal weights) | 61 | Inter-rater unreliable |
| Treating L1 satisfaction as L2 learning | 104 | False positive on training effectiveness |
| Picking strategy before knowing knowledge level | 47, 64 | Strategy mismatch — cute lectures for high-transfer goals |
