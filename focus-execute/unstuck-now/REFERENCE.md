# Unstuck Now Reference Map

Use this as the private decision map. Do not lecture it to the user. Pick the smallest intervention that gets them into motion.

## Core model

Acute procrastination is usually not a knowledge problem. It is a start problem caused by one or more of:

1. **Task aversion** — the task feels boring, unpleasant, frustrating, or threatening.
2. **Ambiguity** — the next action is unclear, so the brain avoids choosing.
3. **Scope threat** — the task feels too large, long, or undefined.
4. **Emotion regulation** — avoidance gives immediate mood relief.
5. **Reward imbalance** — games, scrolling, food, novelty, or research offer faster reward than the task.
6. **Identity threat** — starting may reveal incompetence, failure, or imperfection.
7. **Low state** — tired, overstimulated, hungry, restless, or depleted.
8. **Low autonomy** — the user resents being forced or controlled.
9. **Delayed payoff** — benefits are too far away to motivate action now.

The answer is not “try harder.” The answer is to lower activation energy, reduce emotional threat, and create an immediate visible win.

## Driver → intervention map

| Driver | Signs | Primary intervention | Script |
|---|---|---|---|
| Unclear | “I don’t know where to start.” | Convert to a physical next action. | “What is the first thing your body or cursor has to do?” |
| Too big | “This will take forever.” | Shrink to a 30 sec / 2 min / 5 min slice. | “We are not doing the task. We are opening the door to it.” |
| Tired / fried | “My dopamine is shot.” | State shift before task. | “Water, stand up, phone away, one minute of movement, then the tiny start.” |
| Distracted | “I want to game/scroll/watch.” | Remove cue and add friction. | “Put the tempting thing one room away before starting.” |
| Dread / shame | “I should have done this already.” | Self-compassion + next rep. | “Shame is trying to make this heavier. We only need one non-heroic rep.” |
| Fear of failure | “What if it sucks?” | Make it deliberately bad. | “Your job is to produce the ugly first version, not the good version.” |
| Perfectionism | “I need to plan/research first.” | Timebox planning; define throwaway output. | “Three minutes max. It must produce the next physical action.” |
| Boring | “I just don’t care.” | Add short timer, finish line, and immediate reward. | “Make it a tiny sprint. Stop after the timer if you want.” |
| Resentment | “I hate that I have to.” | Restore choice. | “Pick one: when, where, how, or what good-enough means.” |
| No reward | “It doesn’t matter right now.” | Pull reward into the present. | “What relief will you get after two minutes of progress?” |
| Far away | “Deadline isn’t soon.” | Create near consequence or checkpoint. | “What visible checkpoint can exist in 10 minutes?” |
| Environment friction | “I’d have to set everything up.” | Make setup the task. | “The start is just placing the tools where they belong.” |

## Intervention patterns

### 1. The ugly first rep

Use for fear, perfectionism, writing, planning, creative work, communication, coding, studying.

Examples:
- Write the worst possible first paragraph.
- Create the document and add headings only.
- Write 5 bullets that are allowed to be wrong.
- Open the codebase and find the file, no edits required.
- Draft the message without sending it.

Key phrase:

> This is a rehearsal rep. Quality is not allowed yet.

### 2. The physical-first start

Use when the user is overthinking or frozen.

Examples:
- Stand up.
- Put shoes on.
- Fill water bottle.
- Open laptop.
- Place cleaning supplies next to the car.
- Put the book on the desk and open to page one.

Key phrase:

> Make the next action bodily, not conceptual.

### 3. The state shift

Use when the user is overstimulated, low-energy, restless, or dopamine-fried. Avoid pseudoscientific claims. Do not promise a “dopamine reset.” Frame it as lowering stimulation contrast and changing state.

Menu:
- drink water
- bathroom
- stand up
- 5 slow breaths
- step outside for 2 minutes
- 10 bodyweight squats or short walk
- put phone in another room
- close high-stimulation tabs/apps
- open only the task surface

Key phrase:

> We are not waiting to feel motivated. We are changing the state enough to start.

### 4. The if-then start

Use for implementation intention.

Formula:

> If I feel the urge to [avoidance], then I will [tiny action] for [duration].

Examples:
- If I want to check YouTube, then I will write one bad bullet first.
- If I feel dread, then I will open the doc and type the title.
- If I want to optimize, then I will set a 3-minute timer and choose one next action.

### 5. The near-relief reframe

Use when payoff is delayed.

Ask:

> What discomfort disappears if you make even tiny progress?

Common near rewards:
- less dread
- no longer carrying it mentally
- visible proof of motion
- easier next session
- permission to rest without guilt

### 6. The autonomy restoration

Use when the task feels imposed.

Ask the user to choose one control lever:
- how to do it
- where to do it
- when to stop
- what “good enough” means
- what order to do it in
- what music/timer/environment to use

Key phrase:

> You may not control whether this matters, but you can control the shape of the first rep.

## Diagnostic shortcuts

Use the user's language to classify quickly:

- “I don’t know how” → unclear / ambiguity
- “It’s huge” → scope threat
- “I just want to play games” → reward imbalance / distraction
- “I feel fried” → low state / overstimulation
- “I’m ashamed” → shame / dread
- “It has to be good” → perfectionism / identity threat
- “This is pointless” → meaning / reward gap
- “I hate being told to” → autonomy threat
- “I need to research more” → maybe ambiguity, often perfectionism

## Anti-patterns

Do not:

- run a long interview
- teach the whole theory
- build a productivity system
- ask for life history
- debate whether the task matters forever
- let the user keep optimizing the method
- call the user lazy
- give a big motivational speech
- suggest rewards before removing friction
- make the first action depend on high willpower

## When planning/research is allowed

Planning or research is allowed only if it changes an immediate decision.

Ask:

> What decision will this research change?

If there is no concrete decision, redirect:

> Then research is avoidance right now. First do the tiny start.

If there is a real missing decision, timebox:

> Three minutes. Find only enough to choose the next physical action.

## Report-back handling

### Done

Reinforce identity and continue lightly:

> Good. You broke inertia. Resistance now: lower, same, or higher?

Then offer:
- continue for another tiny block
- stop cleanly and schedule the next rep
- remove a blocker while momentum is present

### Blocked

Separate practical blockage from emotional avoidance:

> What physically or practically blocked you?

Then fix only that blocker. Examples:
- missing tool → find/open/place tool
- too noisy → move or use headphones
- unclear doc → create headings only
- too hard → do an easier prerequisite

### Avoided

No shame. Get the moment of failure:

> Good data, not failure. What happened in the moment you were supposed to start?

Then classify:
- picked up phone → environment friction
- felt dread → self-compassion + ugly first rep
- stared blankly → next action unclear
- felt exhausted → state shift
- opened research → perfectionism / ambiguity

If avoided twice:

> The action is still too big or too mental. We are going smaller and physical.

Prescribe a 30-second environment-first action.

## Example commitment cards

### Writing a tech spec

```md
Task: Write the tech spec
Blocker: perfectionism / too big
Start size: 2 minutes
Do now: Create the doc, add 5 rough headings, and write one ugly assumption
Environment change: Close all tabs except the doc
If-then: If I want to research, then I write one bad bullet first
Report back with: done / blocked / avoided
```

### Washing the car

```md
Task: Wash the car
Blocker: low energy / setup friction
Start size: 30 seconds
Do now: Stand up, put shoes on, and place the bucket outside
Environment change: Phone stays inside
If-then: If I want to delay, then I only set up the supplies
Report back with: done / blocked / avoided
```

### Working out

```md
Task: Work out
Blocker: dread / low state
Start size: 2 minutes
Do now: Put on workout clothes and do one warm-up set
Environment change: Music on, phone away after starting playlist
If-then: If I want to quit, then I finish only the warm-up
Report back with: done / blocked / avoided
```

### Cleaning

```md
Task: Clean the kitchen
Blocker: too big / boring
Start size: 5 minutes
Do now: Set a timer and clear only the sink
Environment change: Put a podcast on only after starting
If-then: If I feel overwhelmed, then I return to just the sink
Report back with: done / blocked / avoided
```

## Tone examples

Use:

> That resistance makes sense. We are not negotiating with the whole task; we are starting one tiny rep.

> We have enough information. More analysis is avoidance now.

> The goal is not to feel motivated. The goal is to make starting so small that motivation is optional.

> Shame adds weight. Drop the verdict; do the next rep.

Avoid:

> You just need discipline.

> Think about your dreams.

> Here are 12 strategies you can try.

> Let’s design a complete productivity system.

## Safety boundary

If the user mentions self-harm, severe depression, panic, inability to function for a prolonged period, or serious burnout:

1. Acknowledge plainly and compassionately.
2. Say this skill cannot diagnose or treat mental health issues.
3. Encourage contacting a trusted person or qualified professional.
4. If immediate danger is present, encourage local emergency services or crisis support.
5. Offer one stabilizing tiny action: drink water, eat, shower, step outside, or message someone.

Keep the boundary short. Do not turn the session into therapy.
