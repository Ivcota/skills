# Execute

Execute is the system-design phase. The goal is not to force essential work harder, but to remove friction so the vital few can move with less drag. Source: `index_split_007.txt`, `index_split_055.txt`.

## Use Execute When

- The essential work is known but repeatedly stalls.
- Deadlines rely on best-case assumptions.
- The team keeps adding effort without finding the constraint.
- Motivation fades after a big start.
- Attention fragments in the moment of action.

## Practices

### Buffer

Create space for unexpected events. The book recommends buffers for time, risk, social consequences, financial impact, and project resilience. Sources: `index_split_057.txt`.

Fast version:

1. Estimate time.
2. Add a 50 percent buffer when appropriate.
3. Ask what could go wrong.
4. Invest early to reduce the highest risk.

### Subtract

Find the primary obstacle before adding more effort. The "slowest hiker" metaphor points to the constraint that controls the pace of the whole system.

Prompt:

- "What is the slowest hiker?"
- "What obstacle, if removed, would make everything else easier?"

Sources: `index_split_058.txt`, `index_split_059.txt`.

### Progress

Make small wins visible. Ask for the smallest useful action that creates momentum.

Prompts:

- "What is the minimum viable progress?"
- "What can be done in ten minutes?"
- "How will progress be visible?"

Source: `index_split_060.txt`.

### Flow

Build routines around cues so essential behavior becomes automatic.

Examples from the text include journal placement as a cue, doing the hardest thing first, and weekly themes. Sources: `index_split_061.txt`, `index_split_063.txt`.

### Focus

Ask what is important now. When overloaded, list competing demands, cross off what is not important now, and act on one essential thing.

Sources: `index_split_064.txt`, `index_split_067.txt`.

### Be

Essentialism deepens when it becomes identity rather than an occasional tactic. Source: `index_split_069.txt`-`index_split_071.txt`.

## Common Failure Modes

| Failure | Symptom | Correction |
|---|---|---|
| Best-case planning | Everything runs late. | Add buffers. |
| Optimizing nonconstraints | Work increases without progress. | Find the slowest hiker. |
| Grand starts | Motivation collapses. | Start with small wins. |
| Accidental routines | Defaults serve the nonessential. | Rebuild cues. |
| Multifocus myth | The user tries to concentrate on many things. | Ask what is important now. |
