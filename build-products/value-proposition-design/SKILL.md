# Value Proposition Design

Use the Value Proposition Canvas to clarify customer needs and proposed value, then test the match. This partial-book skill draws on the publisher excerpt and identified Strategyzer supplements. See [sources.md](sources.md) for attribution and coverage.

## Core principle

Work on one customer segment at a time. Separate what customers need from how the offer creates value. Customer evidence determines whether the proposed match holds. See [Canvas](references/canvas.md).

**The foundation:** Fit requires addressing customer priorities; a completed canvas still needs testing. See [Canvas](references/canvas.md) and [Test](references/test.md).

## The Value Proposition Design framework

Preserve the book's main-section order. The application is iterative.

1. **Canvas.** Map the customer profile, value map, and fit. See [canvas.md](references/canvas.md).
2. **Design.** Explore alternatives from customer insights or existing assets. See [design.md](references/design.md).
3. **Test.** Investigate needs, solution preferences, and payment. See [test.md](references/test.md).
4. **Evolve.** Revisit the offer and its business context. Coverage is limited. See [evolve.md](references/evolve.md).

## Value Proposition Design process

This is an editorial agent workflow grounded in the linked references. Iterate when evidence changes the design.

1. Establish the segment and available evidence. Draft the profile and value map separately. See [Canvas](references/canvas.md).
2. Explore alternatives and explain the choice. Asset-first work still ends with customer validation. See [Design](references/design.md).
3. State the uncertainty and propose a test. Report observations separately from guesses. See [Test](references/test.md).
4. Reassess the design and the kind of fit supported. See [Canvas](references/canvas.md).
5. Identify changed assumptions worth revisiting. See [Evolve](references/evolve.md).

Return the worksheet's [working output](references/checklist.md#working-output). Ask for missing context only when it changes the application. Otherwise label assumptions explicitly.

## Common mistakes

| Mistake | Why it fails | Fix |
| --- | --- | --- |
| Mixing customer segments | Priorities become ambiguous | Use separate profiles. [S8, “Mixing customer segments”] |
| Describing only functional jobs | Social and emotional aims disappear | Examine those aims too. See [Canvas](references/canvas.md). |
| Calling a mapped match validated | A drawing supplies no customer confirmation | Gather evidence. See [Canvas](references/canvas.md). |

## Quick diagnostic

These questions are editorial applications of the references.

| Question | If no | Action |
| --- | --- | --- |
| Is the profile for one segment? | Priorities are unclear | Separate profiles. See [Canvas](references/canvas.md). |
| Were alternatives explored? | The choice lacks comparison | Explore other value maps. See [Design](references/design.md). |
| Does evidence address the current uncertainty? | Fit remains a hypothesis | Propose a relevant test. See [Test](references/test.md). |
| Have changed assumptions been reconsidered? | The offer may need revision | Revisit the business context. See [Evolve](references/evolve.md). |
