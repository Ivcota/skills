# Design

**Core concept:** Explore alternative value propositions before choosing what to build. Start from customer insights or available resources, then validate fit with customers. [S1, p. 49; S5, “Making the most of what's available”]

**Why it works:** Existing technology, capabilities, or patents create starting points; customer testing determines whether the proposed value matters. [S5, “Making the most of what's available”]

**Key insights:**

- An idea alone can start with the customer profile. An established organization can start with a resource and sketch possible value maps. Neither starting point proves demand. [S5, both named sections]
- Compare alternatives on shared variables such as price, performance, risk, and service quality. [S4, “Competing for Customers”]
- Prioritize unresolved needs, customer success measures, and meaningful differentiation. Address selected needs well. [S8, “Components of a strong value proposition”]

**Product applications:**

| Existing capabilities | Explore a new offer from an existing asset | Strategyzer illustrates this with Amazon's infrastructure and expertise becoming AWS for enterprise customers. [S5, “Making the most of what's available”] |

**Boundary:** Resource-first design still requires customer validation. [S5, final paragraph of “Making the most of what's available”]
